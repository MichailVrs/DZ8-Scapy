# ДЗ 8 · Анализ cетевого трафика с помощью Scapy 

**Михаил Вражевских · Программирование на Python · 1 курс**

Приложение с графическим интерфейсом записывает обмен между браузером и локальным сервером Gruyere и формирует читаемый HTML-отчёт. В записи видно, как две заметки попали из одной формы в список на странице: браузер передал их методом GET, сервер дважды ответил перенаправлением, а текст обеих заметок появился в HTML списка.

**Материалы опыта:** [запись для проверки в Scapy или Wireshark](evidence/Вражевских_Михаил_ДЗ8_обезличено.pcap) · [HTML-отчёт для скачивания и открытия в браузере](evidence/Вражевских_Михаил_ДЗ8_обезличено.report.html).

## Как посмотреть результат в PyCharm

1. Открыть папку проекта через **File → Open**. Выбрать интерпретатор Python 3 с Tkinter. Решение проверено с Python 3.13 и Scapy 2.8.0. Установить зависимости из `requirements.txt` по предложению PyCharm либо выбрать **Python Packages → scapy → 2.8.0 → Install**.
2. Запустить [scapy_test.py](scapy_test.py) кнопкой **Run**. Нажать **«Разобрать запись Gruyere…»** и выбрать файл из папки `evidence`. Программа покажет отчёт в браузере. Для просмотра уже сохранённого HTML достаточно открыть его двойным щелчком.
3. Для проверки GET, POST и gzip на небольшом примере нажать **«Открыть учебный отчёт»**. Эта кнопка читает синтетический [DZ8.pcap](DZ8.pcap) на порту 8000. [create_example.py](create_example.py) генерирует этот пример из двух запросов и двух ответов.

## Как сделать собственную запись

1. Для живого захвата на Windows установить [Npcap](https://npcap.com/#download). Для локального сервера скачать [архив Google Gruyere](https://google-gruyere.appspot.com/gruyere-code.zip) и распаковать целиком. Оригинальному серверу требуется отдельный Python 2.7, доступный через Windows Launcher. [Инструкция Gruyere](https://google-gruyere.appspot.com/part1)
2. Запустить `scapy_test.py`, нажать **«Запустить локальный Gruyere…»** и выбрать распакованный `gruyere.py`. В браузере откроется локальный стенд. Если сервер уже работает, перейти к выбору интерфейса.
3. Выбрать интерфейс **Loopback** с адресом `127.0.0.1`, нажать **«Начать запись»** и дождаться статуса **«Идёт запись»**. Если Npcap сообщает `Admin-only Mode`, для живого захвата открыть PyCharm от имени администратора.
4. На странице **New Snippet** отправить первую заметку, дождаться отображения списка и повторить с другой меткой. Нажать **«Остановить и открыть отчёт»**. Программа запишет файлы `.pcap` и `.report.html` в папку проекта. В имени новой записи указаны автор, номер ДЗ и время.

## Как устроено решение

| Шаг | Что делает программа |
|---|---|
| Выбор и захват | Интерфейс в `scapy_test.py` передаёт Scapy выбранный адаптер. `AsyncSniffer` слушает в фоне с фильтром `host 127.0.0.1 and tcp port 8008`. Окно остаётся доступным для остановки записи. |
| Сохранение | `PcapWriter` записывает исходные кадры в порядке получения. По окончании захвата файл закрывается и передаётся модулю анализа. |
| Восстановление HTTP | [http_report.py](http_report.py) связывает порт сервера с HTTP в обоих направлениях. `TCPSession` собирает сообщения из TCP-сегментов. HTTP-слой Scapy обрабатывает gzip при наличии соответствующего заголовка. |
| Разбор полей | Для запроса выводятся метод, путь, заголовки, параметры URL и тело. Для URL-кодированной формы поля выделяются отдельно. Для ответа выводятся статус, заголовки и тело с учётом кодировки. |
| Представление | HTML из пакета экранируется перед вставкой в отчёт. Поэтому в браузере видны сами теги и место, в котором появился текст пользователя. |

## Результаты по этапам задания

**Этапы 1–2. Настройка и сбор.** Записан локальный HTTP-обмен на порту 8008. В захвате 162 пакета, из которых восстановлены шесть GET-запросов и шесть ответов. Четыре ответа имеют статус `200 OK`, два — `302 Found`. Обработка gzip проверяется отдельно на синтетическом примере.

**Этап 3. Анализ пользовательского ввода.** HTML формы New Snippet задаёт метод `get`, обработчик `newsnippet2` и имя поля `snippet`. Обе отправки передают значение в строке запроса. Сервер сохраняет заметки между запросами и выводит их текст внутри элементов `div`. В обеих пробах использовались буквенные метки с дефисом. Эксплуатация XSS и исполнение пользовательского JavaScript в браузере по этой записи не подтверждены.

**Этап 4. Сопоставление запросов и ответов.** Общий префикс пути с идентификатором стенда в таблице сокращён. Каждая строка описывает полный цикл отправки одной заметки.

| Текст заметки | Открытие формы | Отправка значения | Ответ обработчика | Что вернул последующий GET списка |
|---|---|---|---|---|
| `HW8-BASE` | `GET …/newsnippet.gtl` → `200` | `GET …/newsnippet2?snippet=HW8-BASE` | `302`, заголовок `Location: …/snippets.gtl` | `200 OK`, HTML с первой меткой |
| `HW8-CHECK` | `GET …/newsnippet.gtl` → `200` | `GET …/newsnippet2?snippet=HW8-CHECK` | `302`, тот же адрес перехода | `200 OK`, в списке сверху новая метка, ниже сохранилась первая |

Фрагменты из последнего ответа (сокращены только отступы):

```html
<div id='0'>HW8-CHECK</div>
<div id='1'>HW8-BASE</div>
```

При второй отправке изменилось значение параметра, а в таблице заметок появилась строка. Метод, обработчик формы, тип содержимого страницы и последовательность статусов остались прежними. Сравнение обычного запроса с подтверждённой XSS-атакой остаётся невыполненным.

## Что изменено в опубликованной записи

В копии из `evidence/` замаскированы значения cookie, идентификатор экземпляра Gruyere и логин. Замены имеют ту же длину, для изменённых пакетов пересчитаны контрольные суммы. HTML-отчёт сформирован повторным чтением этой копии. Число пакетов, размеры кадров, методы, пути обработчиков, статусы и обе учебные метки сохранены. Правила [.gitignore](.gitignore) исключают новые исходные записи, локальный стенд с его базой и секретом, окружение Python и файлы PyCharm.
